# AIおまかせ値下げ交渉 Agent - 仕様書（ハッカソン版）

対象：Mercari AI Agent Hackathon for PM（2026.8.31-9.1）
チーム内で並行開発できるように、役割を3パートに分割しています。

---

## 1. 課題設定（Why / What）

- **Why**：メルカリの値下げ交渉は、コメント欄でのやり取りが心理的ハードルになっている（催促されている感じがする／断りづらい／相場がわからない）。
- **What**：購入者・出品者それぞれのAIが本人の代わりに交渉し、双方が合意した金額だけを人間に最終確認してもらう「AIおまかせ値下げ交渉」機能を作る。
- **今回のスコープ**：実際の決済・DB接続は行わない。3画面（診断／購入者UI／出品者UI）が「同じデータの形」でつながっていることをデモできればゴール。

---

## 2. 全体の制約（ハッカソンルールより）

- リアルDB・本物の社内データ・個人情報は使用しない。
- 必要なデータ（商品・ユーザー・交渉ログ）はすべて自分たちでダミー生成する。
- 技術スタックは自由（Web UI / CLI / Slack Bot / モック組み込みなど）。3パートで技術が揃っている必要はない。
- 完成しなくていい。中途半端でも「Why → What → 動くデモ」が繋がっていることを優先する。

---

## 3. 全体構成（3パート）

```
①プロフィール(マイページ)          ②購入者UI                ③出品者UI
┌─────────────────┐      ┌─────────────────┐      ┌─────────────────┐
│ 性格診断クイズ            │ 商品ページ                │ お知らせ一覧              │
│ (押しの強さ×温度感)        │ →値下げ交渉バトル画面        │ →合意額の確認カード          │
│                    │ →合意額の確認・リクエスト      │ →やりとりの展開表示          │
│ 出力: PersonaProfile   │                    │ →承認 / 見送るボタン         │
└─────────────────┘      └─────────────────┘      └─────────────────┘
         │                      │  ▲                     ▲
         └────── PersonaProfile ┘  └───NegotiationSession──┘
                (①の結果を②が使う)      (②が作ったログを③が読む)
```

3パートは**別々に動くモック**として作って構わないが、下記「共通データモデル」の形だけは揃える。これにより、最後に繋げてデモするか／繋げずに個別デモするかを当日ギリギリまで選べる。

---

## 4. 共通データモデル（最初に全員でここだけ合意する）

他パートとの連携点はここだけ。JSON1つのやり取りだけ守れば、あとは各パート自由に実装してよい。

### 4.1 PersonaProfile（①が作り、②が使う）

```json
{
  "persist": 5,          // 押しの強さ 1-7（1=あっさり引く 7=とことん粘る）
  "politeness": 6,        // 温度感 1-7（1=フランク 7=ですます調）
  "type": "gentleman",     // gentleman / hot_blooded / listener / mypace
  "name": "紳士交渉人",
  "avatar": "🤵"
}
```

- 4タイプの決め方：`persist > 4` かつ `politeness > 4` → gentleman　／　`persist > 4` かつ `politeness <= 4` → hot_blooded　／　`persist <= 4` かつ `politeness > 4` → listener　／　それ以外 → mypace
- 診断未実施の場合は `persist: 4, politeness: 4`（mypace）をデフォルト値として②に渡してよい。

### 4.2 NegotiationSession（②が作り、③が読む・更新する）

```json
{
  "sessionId": "nego_0001",
  "item": { "name": "泥だんご", "listPrice": 3000, "photo": "dummy_url" },
  "buyer": { "name": "ゲスト太郎", "want": 2000, "persona": { "...": "PersonaProfileと同じ形" } },
  "seller": { "minPrice": 2400, "stubbornness": 70 },  // 出品時に設定済みという想定（非公開項目）
  "turns": [
    { "speaker": "buyer",  "message": "もう少しお値下げいただけますか？", "emoji": "🙂", "offer": 2200 },
    { "speaker": "seller", "message": "その価格だと正直厳しいです…",     "emoji": "😟", "offer": 2600 }
  ],
  "status": "agreed",       // in_progress / agreed / stalled / seller_review / completed / declined
  "finalPrice": 2450,
  "createdAt": "2026-08-31T12:00:00Z"
}
```

- `status` の流れ：
  `in_progress`（交渉中）→ `agreed`（AI同士が合意・購入者の最終確認待ち）→ `seller_review`（購入者がリクエストし、出品者の承認待ち）→ `completed`（出品者が承認＝取引成立） or `declined`（出品者が見送り）
  合意に至らなければ `stalled`（決裂、購入者は条件を変えて再挑戦できる）
- ②はこのJSONを作って保存する（本物のDBは使わず、ローカルJSONファイル／`localStorage`／簡易インメモリAPIなど何でもよい）。③はこれを読み込んで表示・更新する。

### 4.3 Notification（②が `status` を `seller_review` にした時点で③向けに1件作る）

```json
{
  "notificationId": "ntf_0001",
  "sessionId": "nego_0001",
  "title": "AIが合意額を提案しました",
  "body": "「泥だんご」に¥2,450の合意提案が届いています",
  "read": false,
  "createdAt": "2026-08-31T12:03:00Z"
}
```

## 5. パート①：マイページ（AI性格診断）

### 目的
購入者が「自分の値下げ交渉AI」の性格を決める画面。診断結果はマイページに保存され、②の交渉設定画面から参照される。

### 画面・フロー
1. マイページ → 「値下げ交渉AIの性格診断」入口
2. 質問画面：7段階ドット選択式の質問（押しの強さ3問＋温度感3問、計6問。追加してもよい）
3. 診断結果画面：4タイプのいずれかをアバター＋タイプ名＋説明文で表示
4. 「診断をやり直す」で再診断可能

### 4タイプ（例）
| タイプ | 軸 | アバター | 一言 |
|---|---|---|---|
| 紳士交渉人 | 押す×丁寧 | 🤵 | 冷静に、何度も丁寧に交渉を重ねる |
| 熱血バーゲンハンター | 押す×カジュアル | 😤 | 勢いと粘りでとことん値切る |
| 聞き上手さん | 引く×丁寧 | 🕊️ | 相手の様子を伺いながら丁寧に譲る |
| マイペースくん | 引く×カジュアル | 😌 | あっさり流れに任せる |

### MVP（必須）
- 6問の診断UI（既存プロトタイプの7段階ドットUIを流用可）
- 診断結果からタイプ判定 → PersonaProfileを出力
- 未診断でもデフォルト値で②が動くようにする

### Stretch（余裕があれば）
- 質問数を増やす／質問文のブラッシュアップ
- 診断結果をシェアできるカード画像化
- 過去の交渉実績（勝率・平均値引き額）をプロフィールに表示

## 6. パート②：購入者向けUI（値下げ交渉バトル画面）

### 目的
商品詳細ページから「AIに値下げ交渉させる」を押すと始まる、購入者から見た交渉体験。既存プロトタイプ（綱引きバー・タイピング演出・合意スタンプ）をベースに拡張する。

### 画面・フロー
1. 商品詳細ページ（実装済み）
2. 「AIに値下げ交渉してもらう」→ 交渉設定画面（①の診断結果＋希望額のみを表示・入力）
3. 交渉バトル画面（綱引きバー／チャットログ／タイピング演出）
4. 結果画面：
   - 合意 → 「合意」スタンプ演出 →「この金額で購入をリクエスト」ボタン
   - 押すと `status: seller_review` にして NegotiationSession を保存 → **ここで③にNotificationを1件発行**
   - 決裂 → 「条件を変えて再挑戦」で設定画面に戻る

### MVP（必須）
- ①のPersonaProfileを読み込んで交渉パラメータに反映
- ダミーロジックでのターン生成（実LLM呼び出しでもダミー生成でもどちらでもよい）
- NegotiationSessionの保存（③が読める形で）
- 「購入をリクエスト」で `seller_review` 状態にする

### Stretch（余裕があれば）
- 出品者からの承認・却下結果を購入者側にも通知として返す（③→②の逆流。時間があれば）
- 間とテンポの演出（入力中の長さ・迷いの一時停止など、既存実装あり）
- 押し切った瞬間の軽い画面シェイクなど

## 7. パート③：出品者向けUI（通知・合意額確認・やりとり展開）

ここが今回新規に設計するパート。既存の購入者フローで作られた `NegotiationSession` を、出品者視点で受け取って処理する。

### 目的
出品者は交渉に張り付いていなくてよい。AI同士の交渉が終わったら通知が届き、合意額とやりとりの要点だけ確認して、最後の承認だけ人間が行う。

### 画面・フロー
1. **お知らせ一覧画面**（既存の下部ナビ「お知らせ」を起点にする）
   - `status: seller_review` のNotificationをリスト表示
   - 未読バッジ表示
2. **通知タップ → 合意額の確認カード**
   - 商品名・サムネイル
   - 「AIが¥2,450で合意しました」を大きく表示
   - 出品価格・自分が設定した最低希望額との差分がひと目で分かる表示（例：出品価格からの値引き幅）
   - ボタン：「この金額で承認する」／「今回は見送る」
   - リンク：「やりとりを見る」
3. **やりとりの展開表示**
   - 「やりとりを見る」を押すとアコーディオンで交渉ログ（チャットUI）を展開
   - 既存の②のチャット吹き出しデザインを流用し、視点だけ反転（出品者側の発言が右寄せ・青、購入者側が左寄せ・グレー）
   - 各ターンの提示額も表示（②と同じ「価格は大きく」のルールを踏襲）
4. **承認 / 見送るの結果**
   - 承認 → `status: completed`。「取引が成立しました」の確認画面
   - 見送る → `status: declined`。理由の簡単な選択（任意）

### MVP（必須）
- お知らせ一覧（NotificationのMockリスト表示）
- 合意額確認カード（承認／見送るボタンで `status` を更新できる）
- やりとり展開（NegotiationSession.turns をそのまま読んでチャット表示）

### Stretch（余裕があれば）
- 出品者の頑固さ・最低希望額を「出品時にすでに設定済み」という体で、プロフィール的な画面で見せる（購入者には非公開のまま）
- 承認時のアニメーション（②の「合意スタンプ」演出を出品者側にも流用）
- 複数の交渉が同時に来た場合の一覧の優先度表示（金額が近い順など）

### 対象外（今回は作らない）
- 出品者側の性格診断・出品フローそのもの（すでに設定済みという前提を崩さない）
- 実際の決済・入金処理

## 8. 進め方（並行開発のコツ）

1. **最初の30分**：3パート全員で「4章の共通データモデル」だけ確定させる。ここがズレると最後に繋がらない。
2. その後は各パート独立して進める。データの受け渡しは、共通データモデルのJSONをダミーで手書きしておけば、相手パートの実装を待たずに自分のパートを作り始められる（②が完成していなくても、③はダミーのNegotiationSession.jsonを読んで先に画面を作れる）。
3. Day1の終わりまでに、各パート単体で「ダミーデータ→画面表示」までは動かしておく。
4. Day2午前で3パートを繋げるか、繋げずに個別デモにするかを判断する。

## 9. デモ台本（ピッチ5分の見せ方案）

1. Why / What（30秒）：値下げ交渉のコメント欄が気まずい、という課題
2. ①診断画面のデモ（30秒）：性格タイプが決まる様子
3. ②購入者UIのデモ（2分）：交渉バトル→合意スタンプ→リクエスト
4. ③出品者UIのデモ（1分30秒）：通知が届く→確認カード→やりとり展開→承認
5. まとめ（30秒）：AIをどう使い倒したか（LLM呼び出し部分・演出のこだわりなど）

## 10. 参考：既存プロトタイプ

購入者UI（②）のベースとして、以下をすでに作成済み：
- 商品詳細ページ（メルカリ本物のUI準拠）
- 交渉バトル画面（綱引きバー、絵文字アバター、タイピング演出、合意スタンプ、間とテンポの演出）
- マイページの性格診断（①そのもの、6問・4タイプ）

③（出品者UI）はゼロから新規設計。②のチャットUIコンポーネントをそのまま流用できるように、デザインシステム（配色・フォント・コンポーネント）は共通のものを使うこと。
